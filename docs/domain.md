# 领域说明

限售股减持受到证券批次来源、解禁条件、股东关系、敏感窗口与披露规则约束。关联账户可能需要合并计算数量，关系变更和监管规则也各有生效时间。计划、成交回报与公告流程保留版本和累计依据，便于证券事务人员复核每次放行决定。

`reference/domain.json` 保存可公开的示例枚举与精度约定。正式业务记录使用稳定标识，并区分业务发生时间（`business_time`）、系统接收时间（`received_at`）和记录版本（流内 `version`）。

## 事实来源与重放

系统采用事件溯源：所有命令（股东/关系/批次/解禁/窗口/规则维护，计划创建、送审、核准、
变更、暂停、恢复、终止，成交回报、撤回、替换，公告创建与确认，放行决定）都以不可变事件
追加到事件日志（默认 `.runtime/events.jsonl`）。读取模型在每次命令/查询时整卷重放：

* 成交按业务发生日排序，乱序到达不影响累计；
* 撤回/替换回报被标记后不参与累计，额度随之回补；
* 同一 `report_id` 只接受一次；
* 关系与规则按各业务日的生效版本选取，历史结论不因事后变更而改写。

## 合并范围

以计划的组合所有人（通常为实际控制人）为根，按有生效区间的关系
（`controller` / `family` / `employee_platform`）收集当日关联账户。区间为半开区间
`[effective_from, effective_to)`：关系生效日起计入，终止日起剔除。成交归属按
**成交当日**的关系判定，因此关系终止后历史成交仍保留在计划与组合的累计中。

## 逐层数量（最严格结果）

放行试算输出多个独立限制层，每层都带规则版本、条款与计算证据：

1. `plan_remaining`：计划拟减数量 − 计划内已成交；
2. `unlocked_holdings`：合并范围已解禁且未减持持仓（执行时绑定申报账户）。
   解禁须同时满足解禁日已到、业绩考核条件已满足、发行人锁定期已满；
3. `controller_secondary` / `controller_block`：实际控制人任意连续 90 日
   集中竞价 ≤ 总股本 1%、大宗交易 ≤ 2%，渠道分别计算、跨计划按组合累计；
4. `director_annual`：董监高账户自然年度转让 ≤ 所持限售股 25%，仅在绑定该账户
   执行时约束组合可减数量，组级查询只作展示。

命中层取最小余量；窗口、计划状态、执行区间、逾期公告为硬性闸门。

## 窗口期

窗口期（如业绩预告敏感期）覆盖判定日且 `blocking=true` 时拒绝放行；与计划执行区间
重叠的窗口即使尚未到来也会在计划详情中列示为冲突预警。

## 披露流程

* **预披露**：核准时拟减数量达到规则阈值（默认总股本 1%）即创建有时限公告；
* **阶梯减持**：组合累计减持每达到一个总股本 1% 阶梯创建公告；
* 公告有 `due_date`（默认触发后 2 个自然日，随规则版本配置），逾期未确认时
  后续放行一律暂停，确认后恢复；计划变更与终止公告为告知性，不阻断放行。

## 计划状态机

`draft → review → active → suspended → active`，`active/suspended → closed`；
草稿与变更送审被驳回分别回到 `draft` 与 `active`。送审中的计划（`submitted_version`
非空）拒绝普通编辑；变更送审期间现行 active 版本继续有效，核准后挂起版本才提升。
所有状态迁移生成新版本，旧版本完整保留。
